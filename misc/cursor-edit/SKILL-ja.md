# Cursor Edit

## 概要

このスキルは **ファイル編集という行為だけ** を Cursor のヘッドレス CLI（`cursor-agent`）に外注する。Claude Code / Codex など、任意のAIエージェントから同じ契約で使う。

- **呼び出し元AIエージェント（頭脳）**: コードを読む・検索する・何をどう変えるか決める・編集指示を書く・結果を検証する
- **Cursor（手）**: 受け取った指示どおりにファイルを書き換える

目的は、編集の重い処理を Cursor 側に逃がして呼び出し元AIエージェントのトークン消費を抑え、全体を高速化することにある。

ただしコスト削減は **大きな編集でのみ** 成り立つ。小さな修正では、自己完結した編集指示を書いて `git diff` を読み返すコストが、呼び出し元AIエージェントが直接編集する場合を上回ることがある。1〜数行の軽微な編集にこのスキルを無理に適用しない。

## 使いどころ

次の傾向がある。

- **trivial な編集（1〜数行）には向かない**。起動・指示作成・差分確認のコストが、呼び出し元AIエージェントが直接編集する場合を上回りやすい。
- **向くのは「重く・パターンが豊富で・真似できる良い兄弟ファイルが在る」編集**。例: 既存テスト群に倣ったテストケース追加。cursor-agent は良い兄弟ファイルを忠実に踏襲し、規約準拠の結果を短時間で出しやすい。
- **兄弟例が無い新機能・前提が非自明な編集には注意**。cursor-agent は **意味的な検証をせずパターンマッチするだけ** なので、良い兄弟例が無いと正しさを担保できない。この場合は呼び出し元AIエージェントが結果の意味的正しさを別途検証する（「検証の必須化」を参照）。
- **トークンは Cursor 側が消費する**。呼び出し元AIエージェントのトークンは節約できるが、速度・品質の優位は上記の「向く」条件下に限られる。

## 動作契約（このスキルが有効な間）

- 呼び出し元AIエージェントは `Edit` / `Write` / `apply_patch` などの直接編集ツールを **使わない**。
- ファイル内容の書き換えは必ず `scripts/cursor-agent-print.sh` 経由で `cursor-agent` に依頼する。
- 呼び出し元AIエージェントが自分で担うこと: コード読解・検索・計画・編集指示の作成・git 操作・ビルド/テスト/lint による検証・TODO 管理・このスキルのメモリ書き込み。
- これは soft な契約である。hook で直接編集ツールを技術的に封じてはいない。呼び出し元AIエージェントが規律として守る。

## 手順（編集のループ）

1. **分析・設計** — 呼び出し元AIエージェントがコードを読み、何をどのファイルでどう変えるかを決める。
2. **編集指示の作成** — 対象ファイルと変更内容を曖昧さなく書く（後述の書き方に従う）。
3. **委譲** — `cursor-agent-print.sh` に指示を渡して `cursor-agent` に編集させる。
4. **検証** — `git diff` で Cursor の実際の変更を呼び出し元AIエージェントが確認し、変更スコープをビルド/テスト/lint する。
5. **再依頼** — 意図とズレていたら 2 に戻り、指示を具体化して再依頼する。

## cursor-agent の呼び出し方

ラッパー経由で呼ぶ。対象リポジトリ（worktree 利用時はその worktree ルート）で実行する。`cursor-agent` はカレントディレクトリのファイルを読み書きする。

```bash
<cursor-edit>/scripts/cursor-agent-print.sh "<編集指示>"
```

`<cursor-edit>` は、このスキルの配置ディレクトリを指す。

内部では次を実行する。

```bash
cursor-agent -p --force --trust --output-format text --model "${CURSOR_MODEL:-composer-2.5-fast}" "<編集指示>"
# -p      : 非対話（print）モード
# --force : 確認なしでファイル変更を適用する
# --trust : ワークスペースを確認なしで信頼する（新規リポでの信頼プロンプトを防ぐ）
```

デフォルトモデルは Composer2.5 Fast（`composer-2.5-fast`）。モデルを上書きするときは `CURSOR_MODEL` を渡す。

```bash
CURSOR_MODEL=gpt-5.5 <cursor-edit>/scripts/cursor-agent-print.sh "<編集指示>"
```

## 編集指示の書き方（重要）

`cursor-agent` は別の AI である。指示が曖昧だと Cursor が意図とズレた編集をする。指示は self-contained に書く。

- **対象ファイルのパスを明示する**（相対パス、または絶対パス）。
- **真似すべき既存の兄弟ファイルを明示する**（例: 「既存の foo-1.test.ts 〜 foo-6.test.ts を読み、その規約に倣え」）。これが品質と規約遵守を最も上げる最重要のレバー。cursor-agent は良い手本があるほど正確に踏襲し、import・命名・ヘルパーの使い方まで揃える。逆に手本が無いと我流に流れる。
- **変更前・変更後が分かるよう具体的に書く**。該当箇所を引用すると精度が上がる。
- **受け入れ条件を添える**（例: ビルドが通ること、関数シグネチャを変えないこと）。
- **スコープを縛る**（例: 「指定したファイル以外は変更しないこと」）。
- **大きな変更は分割する**。1 回の依頼に詰め込まず、複数回に分けて依頼する。

良い指示の例:

```
server/src/domain/foo/foo.ts の Foo.validate() に、this.name.trim() === "" のとき
new EmptyNameError() を返す early return を先頭に追加する。既存のロジックは変えない。
指定ファイル以外は編集しないこと。
```

## スコープと安全

- **委譲する対象**: プロジェクトのコード・設定ファイル。
- **呼び出し元AIエージェントが自分でやる**: git 操作、メモリ書き込み、TODO 管理。
- `cursor-agent` を放し飼いにしない。**編集対象ファイルを必ず指示に明示し**、スコープ外を触らせない。
- **worktree 利用時**: 必ず worktree ルートで `cursor-agent-print.sh` を実行し、「worktree 外のファイルは変更しないこと」を指示に含める。

## 検証の必須化

- 編集後は **必ず `git diff`** で Cursor の実際の変更を呼び出し元AIエージェントが目視する。`cursor-agent` が返す出力テキストを鵜呑みにしない。
  - コスト削減のため、ファイル全体を読み直さず、まず `git diff`（差分のみ）で確認する。
- **生成先を確認する**。`cursor-agent` は cwd 上で動くため、worktree 利用時は worktree ルートで実行し、編集が worktree 内に入ったか・親リポを汚していないかを `git -C <worktree> status` で確かめる。
- **cursor-agent は意味的な前提を検証しない**（兄弟ファイルのパターンマッチで書くだけ）。`git diff` とビルドだけでは主張・ロジックの **意味的な正しさ** は担保できない。新しい/非自明なロジック（このアサーションは本当に成立するか、この API は実在するか 等）は、usecase・兄弟テストの実際の挙動と突き合わせて呼び出し元AIエージェントが意味的に検証する。良い兄弟例が無いときほど重点的に。「無い／存在しない」と断定する前に grep で裏取りする。
- 変更スコープを **プロジェクトの規約どおりに** ビルド/テスト/lint する。

## 失敗時のフォールバック

- `cursor-agent` が見つからない・認証エラーになる → 実行環境の前提が満たされていないことをユーザーに報告する。
- `cursor-agent` が指示どおり編集しない・失敗する → 指示を具体化して再依頼する。
- それでも解決しないとき → 状況をユーザーに報告し、判断を仰ぐ。soft 契約だが、呼び出し元AIエージェントが勝手に直接編集へ切り替えず、まずユーザーに確認する。
